- The worker CLI set in Settings (a routing row's `driver`) now binds: a job never runs on another CLI. When that CLI is full the job is queued as "waiting for <Claude CLI|Codex CLI> capacity" and starts on the same CLI when a slot frees (`cp_dispatch`, `cp_ask`, armed releases); every other refusal (switch off, CLI missing or old, sign-in, usage window, denied model) is named and switches nothing. A PR reviewer may run in its own idle, held author's slot on the same CLI. Only a human's own per-job request (`cp_parent model_pick` with `driver`, recorded on the job) moves a job to another CLI; a parent's `driver: "pi"` or a model-only change no longer does. Behaviour change: a home at `max_concurrent: 1` now queues instead of running pi.

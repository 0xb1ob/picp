P11c stops after run-artifacts, the answer-card units and quality. gate (93 KB) and pipeline (132 KB) stay `convert`;
one follow-up job, P11d, owns them. The PR description carries the measured diff bytes that set this boundary.

P11c-quality-panel drives `CommandPost.qualityPass()` (what the pipeline, the orphan sweep and S15 call) with voters
routed through the home's `routing.json` and real mock-model reviewer workers; P11c-quality-pipeline opts a real
pipeline in through `data/quality.json` and watches a fresh failure promote the live planner once.

P11c-answer-tui queues six cards in a scratch home's outbox and starts a real `pi` TUI on a pty with the command-post
extension: the extension drains them at session start and its `cp-answer` entry renderer draws them; ctrl+o expands.
P11c-run-log dispatches a real mock-model worker on a treehouse pool, reads its log and projection through
`CommandPost.watch`, tears it down, then tears down two seeded failed jobs: one whose log outlived its process and one
with a garbled log. It is `skip` only where treehouse is missing; CI installs treehouse and runs it.

Each control mutated `src/`, failed on the named assertion, and passed once restored. Two mutations did not fail and
are why their units stay retained: counting `wakeup_suppressed` as activity (the suppression lands in the same second
as the teardown that causes it, so `last_activity_at` cannot tell them apart), and keeping `exited_at` across a
respawn (no entry point revives a seeded run without a resumable session).

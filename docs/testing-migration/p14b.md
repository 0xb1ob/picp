Every daemon scenario copies this checkout's `src/service/daemon*.ts` into a scratch home's app dir and runs the real
CLI, outer and (except where a logging stand-in replaces it) inner; the parent, viewer, sender and oneshot roles are
logging stand-ins. Daemon processes run through a node wrapper that preloads `tests/harness/time-scale.ts`, so the
backoff, readiness, 3/10-min, 120-s, 50-min and 20-s timers run 5-30 times fast with their logged times intact.
Each control mutated `src/`, failed on the named assertion, and passed once restored.

#550 carry-overs: the gateway-key refusal classes run through `--gateway-key-file` in P14-install (P14-NC-gk-classes,
P14-NC-gk-length). The version line writes nothing without a UI (P14-version-print, P14-NC-vl-print). Its "no reads
after stop" is not pinned: after session shutdown the line only stats files and writes nothing, and no entry point
observes a stat. The service-alert threshold stays bracketed at 540 s / 660 s: the parent compares `since` with its
own clock at its start-up tick, seconds after the test writes the record, so an exact 599 s / 600 s pair would flake.

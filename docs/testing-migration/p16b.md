Behavior 14, second slice. Settings scenarios start a real `pi --mode rpc` operator session with the cp-bridge
extension on a scratch home and send `settings_get`/`settings_apply` frames to its control socket, the same
frames the viewer's `/api/settings` relays; the viewer itself is started for the page and the skill catalog. Grant policy
and repo-map scenarios drive a real parent through `cp_mandate`, `cp_check` and `cp_dispatch` (`dispatchS29`). The
skills scenario posts dashboard messages to `/api/operator/message` and has the operator session call `cp_parent send`
against `tests/fixtures/fake-parent.mjs`, which logs the prompts it receives.

`routing.test.ts` and `routing-integration.test.ts` stay `convert` for one follow-on: deleting them would add 117,921
bytes of deletions to a review diff already above 250,000 bytes.

Retained, not reachable (each row names its function): `applySettings`'s `writeText`, `readBack`, `append` and
`shippedRouting` seams and `restoreShippedRubric`; `acquireSettingsLock`'s returned record and its `isPidAlive`,
`onBeforeReclaim` and `pid` options; `repoMap`'s injected `git` runner; `validateSettingValue` and the frozen catalog,
including the routing owner's range probes; `readOwnerConsistently`; the static import guard on `src/settings.ts`;
`loadBudgetConfig`'s bad-JSON `ContractError`; and `resolveSkillNames`'s duplicate and `never` refusals.

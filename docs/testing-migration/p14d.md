Three service-health declarations lose a part no process run reaches, so it is no longer tested: the push service's
fetch and the source scan for push imports (cp-health never pushes), the schema check for a very long home path (the
harness fixes the parent's home), and the relay alert's floor (the parent's alert sweep, driven by P14-alerts).

P14-backend runs `src/service/install.ts` from a copy of this checkout with its clock 60 times fast (the
`tests/harness/time-scale.ts` preload), so the 60-s readiness wait and the rollback's settle run in about a second.
The app's `src/service/daemon.ts` is a logging stand-in; systemctl keeps unit state in a per-user dir. Each control
mutated `src/`, failed on the named assertion, and passed once restored.

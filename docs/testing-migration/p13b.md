P13b (job `cp-e2e-migration-p13b-b6nt`) continues behavior 12 in `tests/e2e/schedules.test.ts`. Failure paths no
longer use chmod, which a root runner ignores: 12-3 puts a regular file where `state/pipelines` belongs, so the
pipeline store's mkdir fails with EEXIST, and restores the directory once the failed start has woken the parent; 12-5
puts a directory where `state/schedule-control.jsonl` belongs, so the parent can neither read nor claim the request,
then restores the journal and sees it applied once.

The P13a declaration "a claim that cannot be journaled acts on nothing" moves from 12-5 to
`tests/schedule-control-retained.test.ts`. The parent reads requests and appends its claim on one path; as root only a
directory fails the append, and it fails the read first, so no journal state lets a real parent see a request it
cannot claim. The retained unit injects the failing append and still fails NC-P13-claim. 12-5's unreadable-journal
case is a liveness check (nothing acts, the request is applied once the journal returns): a thrown read error and a
latched size both still pass it, so it claims no control.

12-5 and 12-6 no longer call viewer handlers in-process: a `createViewer` server on the scratch home (--require-tailnet,
a push config naming the origin) serves `GET /api/schedules/control`, `GET /api/schedules/policy` and the
token-bearing `POST /api/schedules/request`, which refuses the approving policy 400 before anything is journaled.

`Scheduler.savePolicy` refuses an approving policy with the same `schedulePolicyErrors` check the viewer POST and the
journal reader run first; its only production caller is the parent's control poll on a journal line the reader already
validated. Dropping the scheduler's check fails the retained declaration and passes 12-6 (NC-P13b-save-guard), so the
declaration is retained verbatim in `tests/schedule-activation-retained.test.ts`.

12-4 now also fires a cp-org-pr-review schedule while held: its skill wake waits with the pr wake and compaction
releases each once. The P13a wake unit's same-process stop/start (one registration given session_shutdown then
session_start) has no entry point: pi's `new_session`, switch, fork and reload each build a fresh extension runtime
(`AgentSessionRuntime.createRuntime`), so it is retained verbatim in `tests/schedule-wake-retained.test.ts`. Observed,
not fixed here: a real `new_session` RPC in the same pi process re-offers an unexpanded anchor (two wakes), because the
fresh runtime starts an empty `woken` set; the "one offer per process" comment in tools-schedule.ts reads otherwise.

12-8 adds cp-org-pr-review schedules through cp_schedule: every config refusal, the run cap floored at
max_reviewers + 2, and update refused on a native schedule. Its parent is launched with `--skill` for each
`parentSkillPaths` entry, as cp-bridge launches it, and reads each recipe from the location pi lists in its system
prompt; the recipe assertions of both deleted files run on that tool result. 12-9 drives `schedule:` labels and the
org run cap through cp_job create and update on a native run; a cp_schedule deactivate is refused while that run is
open.

Retained verbatim: `verifiedRunNowClick`'s refusals (`tests/schedule-org-review-retained.test.ts`) need a journal line
no viewer or parent writes, and NC-P13b-click fails the retained unit while 12-6 passes. The org run cap's legacy half
(`tests/schedule-expand-retained.test.ts`: `scheduleRiskRefusal`, a run window by `created_at`, an unreadable
`created_at`) applies only to an open run with no active native policy. cp_schedule cannot leave one, since deactivate
refuses an open run; NC-P13b-risk-raise fails the retained unit and passes 12-9.

Narrowed: `pendingExpansions` on a closed or non-deferred anchor, and a cron schedule having no anchors, are not
separately pinned. 12-7 pins the offer, the recovery wake text and no offer once expanded. `readParentExpanded` is
pinned only through the cp_job label check (a missing and an unparseable `schedules.json` refuse the label).

Behavior 19, second slice. Each scenario starts `bin/cp-view` on a scratch home with its clock pinned through
`tests/harness/process-clock.ts`, then calls the viewer's HTTP routes or opens the served app in the linkedom tab of
`tests/harness/dashboard.ts`. The tab gains one additive field, `navigator`: the app's own navigator, so a test can stage
a clipboard. Search and CopyReply need dialog, focus and selection, which linkedom lacks: the test file shims
`showModal`/`close`, a tracked `activeElement`, `createRange`/`getSelection` and listener `this`, never the app's code.

The tab is linkedom, not a browser. This slice asserts DOM, text, HTTP and the served CSS text only, never pixels or
layout at 390 or 1440 px.

## Public-consumer reachability

The provider receives neither stale/replayed replacement text nor its original actionable body. The only production calls to `formatStaleWakeup` and `formatReplayedCiWakeup` are in `reviewWakeups`; the context hook removes the replacements. Seeded legacy messages take that same route. There is no transcript persistence or UI send of these generated replacements. S22-envelope and S22-ci assert body suppression and absence of replacement banners; their guard/replay controls fail when actionable history returns. Thus declarations 25 and 40's standalone formatter details have no public consumer. They are redundant-unreachable, not mapped text assertions.

The sole production `new WakeupNotifier` is in `wakeup-surfaces.ts:266`. Its `sendWakeup` accepts no issued_at and stamps the current clock before synchronous checking; `surfaceAnswered` passes only kind/job/keys/projects. No public option or on-disk answer field supplies an old issued_at to this send-time renderer. Deferring transport happens after rendering. At context delivery, answered messages bypass reannotation. Consequently declarations 26, 33 and 38's send-time late-line combination, numeric delays and clock-clamp return values cannot reach a consumer through a seeded old stamp. S22-answer still pins the reachable outcome: a year-2000 answer and year-2999 clock-skewed answer both survive. The age-veto mutation removes them and fails the real-provider assertion. S22-native additionally pins terminal notes and missing jobs. Those consumer outcomes cover the reason these presentation-only checks existed; no internal mocks or clock injection were added.

Declaration 14 also contains injected getter-exception assertions. The real `CiWatchStore.read` catches unreadable/invalid JSON and returns empty state, and `CiWatcher.head` catches its store lookup. Therefore those injected throw flags/journal calls have no disk-seed entry point through this wiring.

P13a (job `cp-e2e-migration-p13-qnqv`) is the first behavior-12 slice. Every case starts real `pi` parents with the
command-post extension on a scratch home; project `demo` sits on a treehouse pool and a mock provider scripts every
turn. cp_schedule is called by the model; dashboard requests are appended to `state/schedule-control.jsonl` exactly as
the viewer journals them; restarts are new parent processes on the same home. Schedules, runs, policies, grants, the
ledger, the fleet and the journal are read back from disk. Each control below changed one guard, failed in the named
case, and was restored.

Four declarations are retained, each for a missing entry point. Two in `tests/schedule-activation.test.ts` assert
that `activatePolicy` and `deactivatePolicy` refuse a dashboard provenance with no journaled claim: their only callers,
the cp_schedule tool and the parent's control poll, pass a provenance after claiming it, so no tool call, journal line
or restart hands them an unclaimed one; 12-6 pins the rest of both. `tests/schedule-cutover.test.ts` keeps its scan
of the policy writers and `tests/schedule-grant.test.ts` its PR4 scan: both read the source tree, which no entry
point exposes.

Narrowed: 12-6 no longer checks that the scheduler keeps the frozen recipe in its in-memory list while a run is
open; it checks the open run's frozen policy instead. The held half of the wake loop is pinned by 12-4 on a pr wake,
not a skill wake. 12-3 runs board and local fires in a parent that is not held; 12-4 runs an answer fire in a held one.

Behavior 09, last slice: the Awaiting-you rows and the answered wake-up through a real pi parent, the command-post
extension and a mock model. Fleet records, pipelines, checkpoints, declared rows, grants and the answered outbox are
seeded on disk; rows are declared by `cp_status_block`, listed and withdrawn by `cp_awaiting`, answered by `cp_decide`,
and the inherited outbox is drained by the parent's own `session_start` and widget tick. Each control was applied
alone to `src/`, failed on the named assertion, and passed once restored.

The skip/snooze dialog and its resolver are retired (`extensions/command-post/awaiting-command.ts` is a read-only
listing; `tests/harness/awaiting-resolve.ts` is test-only), so their units are `redundant-unreachable`: nothing a parent
can call reaches them, and P10f-rows pins that an unanswered row stays open and listing writes nothing. Escalations
are answered only by `cp_decide` (an operator quote, self-answered) and by `cp_next`'s clean close (`selfAnswered`),
so no `es-` wake can be queued today; P10f-wake and P10f-mission pin that neither wakes the parent.

Retained in place, no entry point (re-verified for #534's review): `CommandPost.decisionContext` has no caller in
`src/` or `extensions/`; `WorkerIdentity.mayAskOperator` is never set (`WorkerManager.plan` resolves planner tools
without it, so `QuestionRelay.handle` behind `onDialog` never runs); and cp_decide's `lookupJob`
(`extensions/command-post/tools-mandate.ts`) returns project and kind only, so `decide`'s risk:high branch has no
subject. `scripts/test-migration-check.ts` accepts `retained` for both baseline rows.

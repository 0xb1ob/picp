Behavior 14, last slice. P16-route-default and P16-route-effort start real `pi --mode rpc` parents with the
command-post extension on scratch homes (`dispatchS29`), whose models.json carries each model's effort metadata; they
call `cp_dispatch` with `dry_run` and read /doctor and the session-start notes. P16-route-rubric and P16-route-capacity
drive in-process `CommandPost`s on the same homes: pi's model registry is stubbed at its `find`/`hasConfiguredAuth`
edge and the sub2api gateway at `fetch`, and the capacity launches spawn real mock-provider workers.

#558 re-check (V2): `skill-catalog-retained` keeps only `resolveSkillNames`'s "named twice" and `never` refusals
(P16-skills pins ambiguity, mismatch, empty description and not-installed); `settings-write-retained` keeps only the
`append`, `writeText`, `readBack` and `shippedRouting` seams and `restoreShippedRubric` (P16-settings-write pins the
recovered owners, not_written/changed_since, the 412, the torn line, the real template and an absent routing.json);
`settings-retained` (c) stays, since `validateSettingValue` is compared with every owner's schema over probes no entry
point enumerates. Restored: models.parent unset beside an env pin reads `{env/parent, env, ok}` (P16-settings-write),
a populated home with invalid routing and env is read without a write (P16-settings-read), and an opt-out on an
uncached commit creates no cache (P16-repo-map).

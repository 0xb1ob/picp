Behavior 20. Each scenario starts `bin/cp-view` on a scratch home with its clock pinned through
`tests/harness/process-clock.ts`, then calls the viewer's HTTP routes. Settings writes reach the operator session's own
dashboard-control server (`startDashboardControl`); `tests/harness/dashboard.ts` gains one optional `extra` ports
argument on `operatorSession`, additive only. A stub `pi` on PATH answers `--list-models`. Schedule state is seeded
the way the scheduler, `cp_mandate` and intake leave it; P20-schedules-anchor-notes drives the real `Scheduler`.
`tests/viewer-schedules-retained.test.ts` keeps the units no e2e surface can reach: the schedule schema's constant
mirrors of the contracts, the expander registry against `PARENT_SKILLS` and `skills/*/SKILL.md`, and the viewer's
answer cap against `ANSWER_MAX_BYTES`.

The pages run in the linkedom tab of `tests/harness/dashboard.ts`, not a browser: the rows assert DOM, text, HTTP and
the served CSS text, never pixels or layout at 390 or 1440 px.
